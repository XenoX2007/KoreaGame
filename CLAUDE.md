# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

KoreaGame ("Sân Chơi – Madang") is a 2D local-multiplayer mobile party game: 2 or 4 players share one landscape phone lying flat on a table, each with one button at their seat. Folk mini games: Kéo Co (tug of war), Người Gỗ / Mugunghwa (red light–green light), Đá Cầu / Jegichagi (shuttlecock kicking), Bắn Bi / Gusulchigi (marbles), Tách Kẹo / Ppopgi (candy cutting) and Lẩu Tokbokki / Jeukseok tteokbokki (hotpot race); the last two are played with joysticks. Don't use Squid Game imagery (doll, red suits, masks).

- **Unity version:** 6000.5.4f1 (Unity 6.5), installed at `C:\Program Files\Unity\Hub\Editor\6000.5.4f1\`. Several other editor versions are installed side by side; always use this one.
- **Render pipeline:** URP with the 2D Renderer (`Assets/Settings/UniversalRP.asset`, `Renderer2D.asset`). Use URP 2D-compatible materials/shaders (e.g. `Sprite-Lit-Default`), not Built-in shaders.
- **Input:** Project is set to the new Input System only (`activeInputHandler: 1`). The legacy `UnityEngine.Input` API will throw at runtime; use `UnityEngine.InputSystem` and the actions in `Assets/Settings/InputSystem_Actions.inputactions`.
- **UI:** game UI is UI Toolkit (see below). uGUI remains only for the `InputTest` dev scene (`SeatCanvas`, `UiBuilder` image/text helpers).
- **2D packages:** Sprite, Tilemap (+ extras), SpriteShape, 2D Animation, Aseprite and PSD importers.
- **Player settings:** locked to Landscape Left, Android fullscreen, iOS edge gestures deferred (keeps corner buttons from triggering system gestures).

## Architecture (`Assets/Scripts/Core`)

- `SeatLayout`: per player count (2 or 4 only; 3 is intentionally unsupported) defines each seat's touch zone (normalized full-screen rect), UI anchor (inside safe area) and UI rotation. Ids are arranged so `team = id % 2` (even = left half, odd = right half).
- `PlayerInputRouter`: self-creating `DontDestroyOnLoad` singleton. Maps EnhancedTouch fingers to players by the zone they started in (sticky until lift), plus keyboard (Z/P/Q/M = P1..P4 by screen corner) and mouse for Editor testing. Emits `PlayerInput(id, pressed)` only on 0↔1 transitions of held sources. Mini games must never read touches directly. `RegisterExtraZone(id, rect)` adds a shared button over the seats with ids from `SeatLayout.MaxPlayers` up (Space presses the first one in the Editor); `IgnoredZones` win over it, and `Configure` or `ClearExtraZones` remove it. `Stick(id)` is a polled per-seat joystick in screen space (y up, length 0..1): the drag of the seat's first finger from where it went down, divided by `StickRadius` (9% of screen height); in the Editor WASD / arrows / IJKL / numpad 8456 drive P1..P4. `StickActive(id)` is true while something drives it.
- `MiniGameBase`: subclasses implement `Setup(playerCount)`, `OnPlayerInput`, `GetRanking()` (rank per player id, 1 = best, ties share rank; use `RanksFromScores`), and call `Begin()`/`Finish()`. Playing a mini-game scene directly uses its `editorPlayerCount`; otherwise `GameManager.Instance.PlayerCount`.
- `GameAudio`: creates itself at startup and persists, so music continues across scenes. Clips load from `Assets/Resources/Audio`. It owns the only `AudioListener`, because scene cameras have none. The music ducks while the victory fanfare plays, which happens at round end unless `HasWinner` is false, and on the podium when the cup reaches the top.
- `OnlineSession` (`Assets/Scripts/Online`): online play, one phone per player, Kéo Co only so far. Self-creating and persistent. The host creates a private room through `Unity.Services.Multiplayer` (`CreateSessionAsync(...WithRelayNetwork())`, anonymous sign-in, project linked to Unity Cloud) and others join by its code or by the `madang://join/CODE` link (`JoinLink`; Android intent filter in `Assets/Plugins/Android/AndroidManifest.xml`; a desktop build also accepts `-join CODE`). The `NetworkManager` is added at runtime with scene management off: phones exchange Netcode named messages (`Listen`, `SendToHost`, `Broadcast`) and each loads scenes itself via `GameManager.StartOnline`. Only the host runs the rules. `PanelMiniGame` handles the online round: joining phones send presses stamped with the network clock, `Now` is that clock online, a round starts once every phone reports ready, and each phone shows only its own seat (no pause). `OnlinePanel` is the menu card. A host leaving ends the game for everyone; shut the network down before leaving the room, or the relay logs errors (which also trip the Editor's Error Pause).
- `GameManager`: persistent, lives on its own object in the `Menu` scene (a duplicate destroys its whole GameObject on returning to the menu, so don't put other components on it). Session mode (single/tournament), scores (3/2/1/0 points), scene flow via `Continue()`/`ReturnToMenu()`. Tournament order follows the proposal's story: `NguoiGo`, `KeoCo`, `DaCau`, `BanBi`, `TachKeo`, `LauTokbokki`. Menu cards and the tournament button unlock via `Application.CanStreamedLevelBeLoaded`, so a game only needs its scene in the build.
- `PanelMiniGame` (`Assets/Scripts/UI`): base class for UI Toolkit mini games. Owns the `PanelRenderer` lifecycle, seats (`PlayerSeatView` from `PlayerSeat.uxml`), the results card (`ResultsOverlay`, whose fun facts hold Vietnamese, Korean and English) and the 1v1/2v2 switch. A subclass implements `Bind(root)` and `FunFacts`, calls `EndRound(title)`, and its HUD must contain `seatLayer`, `timer`, `centerMessage`, `togglePlayers` and instances of `ResultsOverlay.uxml` and `PauseOverlay.uxml`. Pausing stops the round through `PausableClock` (`Now` and not `Time.timeScale`, which rounds ignore) and disables the component, so no `Update` runs; presses are dropped while paused. The pause button is an `IgnoredZones` entry on the router, because seat zones cover the whole screen.
- `CharacterView` (`Assets/Scripts/UI`): a player drawn as their character, left team Vietnamese and right team Korean. `Face(direction)` picks front, back or side (the side art looks right, flipped for left). The background is side-on with its horizon at 60%, so everyone stands on the ground band (`FarGround`..`NearGround`) instead of at their seat: the far long side stands at the horizon, the near side close to the camera, and `DepthScale` sizes them. `AddArm` swaps the side view for the `*_side_pull.png` art, which has the hanging arm painted out, and adds the arm piece. Seat discs are `Button_P1..4.png`, redrawn from `Buttons.png` without its dark stand.
- `Localization` (`Assets/Scripts/UI`): all UI text is in the language picked with the globe button on the menu (Vietnamese, Korean or English), saved in `PlayerPrefs`; the first run follows the device language. UXML and code keep the Vietnamese; add each new string with its Korean and English to the table (`LocalizationTests` checks UXML text). Static text uses `Bind(root)`, per-frame text `Text(...)`, and line sets such as fun facts (Vietnamese, Korean, English) use `Pick`. Chants deliberately stay in their own language.
- Korean text: `JuaSDF` is dynamic and clears its glyphs on build, so its 2048 atlas fills from `Jua-Regular.ttf` at runtime. Letters that spill onto a second atlas page vanish from the text with no error, so every Hangul letter the game uses must fit on one page; `LocalizationTests.EveryKoreanLetterFitsOnOneAtlasPage` checks that with a fresh copy of the font.
- `PodiumCelebration` + `Confetti` (`Assets/Scripts/UI`): the end-of-tournament show. Rank 1 lifts the cup (`CharacterView.HoldCup`/`Raise`, using `*_front_cheer.png`, which has the arms painted out, so they do not double up), everyone sways, and confetti bursts from the cup with light rays behind. Confetti is pooled UI Toolkit elements, because a world particle system would sit behind the panel.
& (`Place` negates seat rotation because USS rotates clockwise), `FitSafeArea`, and `Reveal` (adds a class after first layout so USS enter transitions play).
- `SeatCanvas`/`UiBuilder`: uGUI helpers for `InputTest`. `UiBuilder.EnsureEventSystem` is also used by UI Toolkit scenes: panels receive input through an `EventSystem` with `InputSystemUIInputModule`, created at runtime.

### UI Toolkit (`Assets/UI`, scripts in `Assets/Scripts/UI`)

- Screens use the Unity 6.5 `PanelRenderer` component (not `UIDocument`). There is no `rootVisualElement`: get the root from `RegisterUIReloadCallback((panel, root) => ...)`, which may fire before or after `Start`. Register in `Awake`, unregister in `OnDestroy`. An exception in the callback leaves the panel blank.
- `MadangPanelSettings.asset` uses our own `MadangTheme.tss` → `Madang.uss` (design tokens, fonts, `.btn`), not Unity's default theme, so nothing is styled by default and the theme must itself stretch `.unity-ui-document__root`.
- Fonts: `MaliBoldSDF` (Latin + Vietnamese) with `JuaSDF` fallback (Hangul), both OFL. Icons are native SVG (`Assets/UI/Art`, imported as `VectorImage`). The background and characters are hand-drawn PNGs in `Assets/UI Assets`; USS picks a view by its sprite slice (`KR.png`, `VN.png`). `NPC_back.png` is `NPC.png` with the face painted over as hair.
- `filter` and `transition-property: filter` are valid USS in this version. Filters render the subtree to a texture, so apply them only to static moments (`.is-finished .field`), never during a round. A panel's HUD elements use `picking-mode="Ignore"`; gameplay input always comes from `PlayerInputRouter`, never UI Toolkit.
- Screens are UXML/USS in feature folders: `Menu/`, `KeoCo/`, `NguoiGo/`, `Podium/`. Seat, results, timer and field styles shared by mini games live in `Madang.uss`.

Each mini game is split into a pure rules model (explicit `double time` arguments, no Unity lifecycle, unit-tested) and a `MiniGameBase` view/glue component:

- `Assets/Scripts/KeoCo/KeoCoModel`: beats precomputed from a BPM curve (tempo ramps up in the last `rampSeconds`); taps are judged Perfect/Good/Miss by distance to the nearest beat; one scoring tap per beat; an off-beat tap loses grip for `slipSeconds` (re-armed by further taps) so mashing can't beat rhythm; teammates hitting the same beat within `syncWindow` get the "Đồng lòng" bonus; ribbon position in [-1, 1] uses exactly integrated damped velocity (frame-rate independent); win at ±1 or by side at timeout. All tuning is in the serializable `KeoCoSettings` on `KeoCoGame` (Inspector).
- `KeoCoGame`: countdown → round → results overlay (Chơi lại / Về menu, or Tiếp tục in a tournament); when played without a GameManager, a bottom-center button switches 1v1/2v2 outside rounds. `TrackHalfWidth` must match `.win-line` in `KeoCoHud.uss`.
- `Assets/Scripts/NguoiGo/NguoiGoModel`: hold to run, release to stop. Each caller cycle is a timeline generated up front from a seed: chant (normal, fast, or last syllable stretched; Vietnamese and Korean alternate), an optional mid-chant `Tell` + `Fake`, then `Tell` → `Turning` (reaction grace) → `Watching`. Anyone held during `Watching` returns to the start. First to reach the caller wins; `roundSeconds` is a safety limit where the closest wins. A test guarantees the tell always precedes watching. Tuning is in `NguoiGoSettings`.
- `NguoiGoGame`: the caller stands in the center with lanes across the ground from each side. `CallerGround` must match `.caller` in `NguoiGoHud.uss`. The tell is deliberately subtle (a shoulder twitch, no color change). Fake turns keep the caller's back turned, because a visible face must always mean "you can be caught".
- `Assets/Scripts/DaCau/DaCauModel`: every kick or serve flies to a random other player still in the game, so nobody can stop watching; with two left it goes back and forth. Only the receiver can kick, from `ZoneStart`: tapping in the zone before the Good window costs a life (so mashing loses), no tap by the end of it does too. Perfect flies faster; flights speed up with the rally down to `minFlightSeconds`; wind can start in long rallies; feather and jegi swap after every drop. Last player with lives wins.
- `DaCauGame`: the seat ring closes exactly as the shuttle arrives; players stand at the landing spots, and a kick hops and swings them back then through (`Tilt`). Shuttle height is drawn with a separate ground shadow. The timer pill shows the rally count.
- `Assets/Scripts/BanBi/BanBiModel` (spec: `docs/BanBi_v2.md` plus the field changes in `docs/BanBi_v3.md`; both supersede `docs/BanBi.md`): top-down team marbles in a circle (zone units, radius 1, +y up; `IsOut` is `magnitude > 1`). Marbles belong to teams (VN = left, blue marbles from `VN (Blue).png`; KR = right, red marbles from `KR (Red).png`, matching the art), 4 each at start (set in the BanBi scene; the code default is 6). Dice decide the order (only tied players reroll; teams alternate). On a turn the hand slides along a straight line under the circle (`HandX`); press stops it, hold charges triangle-wave power, release shoots a new marble straight up from `launchY`, appended to `Marbles`. Fixed-substep physics (`BanBiPhysics`); once everything stops, marbles that moved and are outside the circle are removed. A rival marble out gives a bonus shot; a team with none left loses; after `shotsPerTeam` each, more marbles wins (then closest to center).
- `BanBiGame`: the circle, marbles, seats, side columns (team counters; a turn row with the turn count and a separate countdown pill; the first-turn hint) and shoot button are sized and placed in code from the stage height every frame; USS holds only their look. Seat visuals are pulled in next to the circle with a `translate` (touch zones unchanged), and the pause button moves to the top-left in this scene. Seats only stop dice; during turns the shared shoot button (router extra zone `ShootId` = 4, registered only while it shows) presses for `ActivePlayer`, and seat presses are ignored. The hands are the arm slices `VN.png#VN_4` / `KR.png#KR_3`, rotated 180° in USS to point up. The aim line is pooled dots (no dashed borders in UI Toolkit). Marbles and held marble are the team art; the shoot button and team counters use the team color (VN blue, KR red). The menu card shows both marbles together. Dice are still placeholder squares and there is no sfx yet.
- `Assets/Scripts/TachKeo/TachKeoModel` (spec: `docs/TachKeo.md`, look: `docs/TachKeo.html`): everyone at once, each for themselves. Each player steers a needle around a stamped outline (`TachKeoShapes`: umbrella, square, oval, star, all scaled to the same perimeter, shuffled by seed so nobody shares one) in candy units (radius 1, +y away from the player). Fixed substeps; `SetStick` first advances with the previous stick. The needle carves and cracks only while the stick is active (> 0.05), so an untouched candy stays at 0%. Off the line or tilt above `pushThreshold` fills the crack meter, careful cutting heals it; a full meter breaks the candy and a fresh one arrives after `restartDelay` while the round clock runs on. Ranking: finishers by time, then carved count (a broken candy counts 0); `HasWinner` is false only if nobody carved anything.
- `TachKeoGame`: rotates `Stick(id)` by the inverse seat rotation into candy space. Seat discs become joysticks (the seat ring is the base, a knob shows the stick, a status line shows %, "Vỡ rồi!" or the time). Tins are sized from the stage height and then fitted inside the player's quadrant/half clear of their joystick (`FitTin` shrinks them, e.g. 2 players at 16:9). Candy, stamped line, carving, cracks, needle, shards and progress ring are one `Painter2D` element per player. The countdown shows in the timer pill (centered with 4 players). No sfx yet (the spec's `tachkeo_*` clips don't exist).
- `Assets/Scripts/LauTokbokki/LauTokbokkiModel` (spec: `docs/LauTokbokki.md`, look: `docs/LauTokbokki.html`): top-down, everyone at once, each for themselves, on a 16 × 9 arena (arena units, y up; `LauTokbokkiLayout` holds the table, pens, pots and spawns per player count). Each player has a seeded 5-item recipe (≤ 2 of a kind). A table spins clockwise with 12 plate slots (8 filled at start; slots empty at start stay empty, a taken plate refills `refillSeconds` later, usually with something someone needs). Players walk with the stick (eased velocity, circle collisions with each other, the table, pots and walls), pick up needed items automatically, and drop them in their pot by walking into their pen. `Action` (a tap) puts the carried item into the nearest pot in reach (unneeded = spoiled, blocks perfect), drops it on the floor, steals the last correct item from a rival's pot (`stealCooldown`), or lets the owner take a spoiled item out. Reach is measured edge to edge (player edge to plate/pot edge); center to center the table would keep every plate out of reach. A hard hit (closing speed > `bumpSpeed`) stuns the slower player and knocks their item to the floor. First perfect pot wins; at time up the single highest correct count wins, a shared top is a draw. `SetPosition`/`SetCarried`/`SetPlate`/`SetVelocity` are test hooks.
- `LauTokbokkiGame`: all its art is in a serialized `LauTokbokkiArt` (sprites from `Assets/UI Assets`, assigned by `ProjectSetup.CreateLauTokbokkiScene`, so regenerate the scene rather than editing it). The floor maps arena units to `stage.y / 9` px, centered; tile lines and pens (tint plus a fence on three sides, open toward the table) are one `Painter2D` element. Recipe cards are built at 1080-tall size and scaled. A tap is a press shorter than `tapSeconds` whose stick never went above 0.3. Seats use the shared `.seat--joystick` look from `Madang.uss`. No sfx yet.
- `Assets/Scripts/Prototype/InputTestGame` + `Assets/Scenes/InputTest.unity`: multi-touch device test.
- Menu `KoreaGame/` (`Assets/Editor/ProjectSetup.cs`): `Create UI Assets` (font assets, panel settings), `Create Da Cau Scene` (regenerates DaCau and Menu), `Create Ban Bi Scene` (regenerates BanBi and Menu), `Create Tach Keo Scene` (regenerates TachKeo and Menu), `Create Lau Tokbokki Scene` (regenerates LauTokbokki, with its art, and Menu), `Create UI Scenes` (regenerates everything including KeoCo, resetting Inspector tuning; Menu becomes the first build scene), mobile player settings. Scene creation regenerates the scene from scratch; load assets inside the scene step, because `NewScene` unloads unreferenced ones.

Enter Play Mode Options have **domain reload disabled**, so every static field needs a `[RuntimeInitializeOnLoadMethod(SubsystemRegistration)]` reset.

## Commands

There is no CLI build/lint script; work is normally done in the Unity Editor. `.csproj`/`.slnx` files are generated by Unity — don't edit them by hand (regenerate via Editor > Preferences > External Tools).

The Unity CLI (`unity`) can drive the open Editor through the `com.unity.pipeline` package: `unity command console status`, `unity command eval --code '...'` (code runs inside a method body: no `using` lines, fully qualify types), `unity command start`/`stop` (Play Mode). When the Editor window is unfocused, run `unity command set_auto_tick --enable true` or frames won't advance; disable it afterwards. In Play Mode that may not be enough: a frozen `Time.frameCount` looks like a blank scene, so also set `Application.runInBackground = true` through `eval`. `capture game_view --save_path` is relative to `Assets/`, so delete those files afterwards. Input injected from outside the game (`simulate_key`, queued touch events) doesn't reach Play Mode unless the Game view has focus, so test input through the test fixture below instead.

### Tests

Game code is in the `KoreaGame` assembly (`Assets/Scripts/KoreaGame.asmdef`). PlayMode tests live in `Assets/Tests/PlayMode` (`KoreaGame.Tests.PlayMode`). Input tests derive from the Input System's `InputTestFixture` (enabled through `"testables": ["com.unity.inputsystem"]` in `Packages/manifest.json`). It fakes touchscreens and keyboards with `BeginTouch`/`MoveTouch`/`EndTouch`/`Press` on an isolated, always-focused runtime. `MenuFlowTests` uses it to tap real scenes through the EventSystem into UI Toolkit, which is the way to test buttons, since `simulate_pointer` doesn't reach an unfocused Game view. A test that loads a scene with a UI panel must unload it in `[UnityTearDown]`: otherwise Unity's `InputSystemProvider` outlives the fixture's fake input system and later touch tests fail with a `NullReferenceException` inside that provider.

With the Editor open (PlayMode tests must run async; results land in `Temp/pipeline_test_status.json`):

```
unity command set_auto_tick --enable true
unity command test run --mode PlayMode --filter KoreaGame.Tests.PlayMode --filter_type assembly --async_tests true
unity command test status
```

Pass a test's full name as `--filter` (without `--filter_type assembly`) to run a single test. With the Editor closed: `"C:\Program Files\Unity\Hub\Editor\6000.5.4f1\Editor\Unity.exe" -batchmode -projectPath . -runTests -testPlatform PlayMode -assemblyNames KoreaGame.Tests.PlayMode -testResults TestResults.xml -logFile -` (use `-testFilter <name>` for one test).

## Conventions

- Every asset and folder under `Assets/` has a `.meta` file holding its GUID. When creating, moving, or deleting files outside the Editor, keep the `.meta` file alongside it (and commit both); never regenerate or hand-edit GUIDs, or scene/prefab references will break.
- `Library/`, `Temp/`, `Logs/`, `UserSettings/` are generated and git-ignored.
- Scene and prefab files are YAML; prefer making changes through the Editor rather than hand-editing them.
